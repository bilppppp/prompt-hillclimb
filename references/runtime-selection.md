# Runtime 发现、选择与引导规范

本文档面向调用 `prompt-hillclimb` 的 AI Agent 与开发者，规范如何在评估前探测、呈现候选并引导用户显式确认 Runtime Executable。

---

## 1. 核心决策原则

1. **用户明确指定优先**：
   - 若用户在输入中明确指定了特定的 Harness 或模型（如指定使用 Codex 或 Pi），必须优先遵循。
   - 若经核验该指定环境存在不可消除的强干扰或无法满足基本隔离要求，应明确向用户说明风险并暂停正式评测，**严禁静默切换至其他 Runtime**。

2. **用户未指定时的发现流程**：
   - 若用户未显式指定，Agent **不得擅自默认当前宿主或任一 Harness**。
   - 依次通过安全的轻量检查进行探测：`command -v` / `which`、CLI `--help` 输出检查、非敏感环境变量与路径存在性检查。
   - **禁止探测敏感信息**：严禁读取或扫描 API Key、Token 文本、账号密码、订阅计划或计费状态。不要为了证明模型身份或认证状态做多余探测，严禁将认证来源作为推荐卖点。
   - 探测完成后，向用户列出可用候选、潜在风险及简短建议，**必须经由用户显式确认选择后，方可进入正式评测流程**。

3. **宿主与未验证 Harness 界限**：
   - 当前正在执行任务的宿主 Agent / Harness，仅在其经过验证满足无工具、无污染单次独立调用的前提下，方可作为候选之一列出；**绝不能无条件默认当前宿主**。
   - 若在环境中检测到其他知名 Coding Harness（如 OpenCode、Hermes、OpenClaw、AGY 等），但仓库内未附带已验证的封装 wrapper，应明确向用户标注为“检测到可执行程序，但尚未验证封装契约”。只有在用户明确选择该方案后，方可基于其最新的 `--help` 制作最小封装并先进行冒烟测试，本工具不默认内置未经全面验证的 adapter。

---

## 2. 候选信息报告维度

向用户呈现 Runtime 候选方案时，应统一依据以下 6 项客观事实报告，避免主观臆测：

1. **可调用性（Invocability）**：CLI 路径是否存在且可执行。
2. **Fresh Session 能力**：是否具备单次调用不记录会话、不污染历史的能力（如 `--ephemeral`、`--no-session`）。
3. **规避项目上下文能力**：是否能脱离当前工作区与 Git 仓库（如支持空临时 `cwd`、`--no-context-files`）。
4. **已知全局污染风险**：是否存在无法完全隔离的全局文件（如 `~/.codex/AGENTS.md`、`~/.pi/agent/SYSTEM.md`）。
5. **Final-only 输出能力**：是否支持仅输出最终回答至 stdout，不混杂工具日志或交互提示。
6. **当前模型信息**：当前默认或配置的模型信息；仅在可靠可得时显示，否则如实标注为 `unknown`，不要为探测模型身份发起额外调用或检查凭据。

---

## 3. 可选 Contract Smoke 验证流程

在用户显式选定 Runtime、且在正式启动 Hillclimb 前，Agent 可在用户授权下执行一次**单次轻量级 Contract 冒烟测试**（注意：这会消耗 1 次 runtime invocation，不同于零调用的 `--dry-run`）：

1. **测试 Prompt**：
   ```text
   直接根据下面提供的文本回答。
   不要读取本地文件。
   不要搜索目录。
   不要使用任何工具。
   不要尝试寻找额外上下文。

   Return exactly: HILLCLIMB_RUNTIME_OK
   ```

2. **验证点**：
   - 进程正常启动且以退出码 `0` 退出。
   - 验证 `stdout.strip()` 是否**精确等于** `HILLCLIMB_RUNTIME_OK`。
   - 确认无调试日志混入 `stdout`，且错误诊断写入 `stderr`。

3. **局限性声明**：
   - 本冒烟测试仅证明 Runtime 满足基本的可执行、stdin 接收与 final-only 文本输出契约；
   - **绝不能仅凭本测试通过就声称 Runtime 实现了绝对的环境或上下文隔离**。

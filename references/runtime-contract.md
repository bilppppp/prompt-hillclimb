# Runtime Contract 规范

本文档定义 `prompt-hillclimb` 与外部执行运行时（Runtime Executable）之间的通用交互契约。
任何符合本规范的可执行程序（脚本、二进制、容器命令封装等）均可直接作为 `--runtime` 参数接入，Core 逻辑不感知底层 Harness、模型类型、提供商或认证凭证。

---

## 1. 核心契约原则

一个合规的 Runtime 必须满足以下 5 条基本要求：

1. **标准输入传递（stdin）**：
   - 每次调用时，完整的 Prompt 文本通过标准输入（`stdin`）以 UTF-8 编码完整传入。
   - Runtime 必须能完整接收多行文本，且不得依赖命令行参数传入 Prompt（规避参数长度限制与特殊字符转义歧义）。

2. **纯净最终回答（stdout）**：
   - 当调用成功时，Runtime 的标准输出（`stdout`）**只能包含模型的最终文本回答**。
   - 严禁向 `stdout` 输出任何辅助日志、进度信息、格式化提示符、状态码或终端 ANSI 颜色转义序列。

3. **诊断与告警通道（stderr）**：
   - 所有的运行时诊断、调试日志、环境变量警告与非致命告警必须写入标准错误（`stderr`）。
   - Core 会保留 `stderr` 用于在失败时排查问题，但绝不会将其混入最终评估回答中。

4. **严格的退出状态码（Exit Codes）**：
   - **退出码 `0`**：表示调用成功完成，且 `stdout` 含有有效的非空回答。
   - **非零退出码**：表示调用失败（超时、网络异常、认证失败、进程崩溃等）。Core 在捕获非零退出后会立即进入相应阶段的错误处理流程。

5. **单次独立无状态（Stateless & Fresh Session）**：
   - 每次调用必须是**全新的、独立的会话**，严禁续接（resume）上一次会话或共享对话上下文。
   - 严禁在调用过程中自动检索或读取本地评估集（`evals.jsonl`）、历史优化产物（`.hillclimb/`）或宿主未授权的代码库历史。

---

## 2. 隔离性边界说明

> [!WARNING]
> **空临时目录不等于绝对隔离**：
> Core 在每次调用 Runtime 时，都会在新的临时空目录（`tempfile.TemporaryDirectory`）中启动子进程，并将 `cwd` 设为该目录。
> 然而，**仅靠切换 `cwd` 并不能保证绝对没有全局上下文或状态影响**。底层执行环境仍可能通过用户全局配置文件、环境变量或系统全局提示词（如全局指令文件、插件系统、跨进程共享守护进程）引入隐式上下文。Runtime 封装层应当尽可能利用底层 CLI 提供的无工具、无扩展、无上下文选项最小化此类影响，并在存在无法关闭的全局影响时向 `stderr` 打印诊断说明。
